# Specification and Plan for BCEA Classification Pipeline

## Overview
The goal of this pipeline is to develop a machine learning model (likely an LLM-based classifier) to predict Belize Classification of Economic Activities (BCEA) codes from textual or structured input data. BCEA is a 5-digit classification system derived from the International Standard Industrial Classification (ISIC), extending ISIC’s 4-digit codes with an additional decimal digit for finer granularity (e.g., ISIC `1234` becomes BCEA `1234.1`, `1234.2`, etc.). This pipeline will process historic BCEA data, map labels consistently, and provide detailed, aesthetically pleasing logging throughout execution.

## 1. Nature of BCEA
### Description
- **BCEA vs. ISIC**: BCEA is a Belize-specific adaptation of ISIC. While it shares a foundational structure with ISIC’s 4-digit codes, BCEA introduces a fifth digit after a decimal point (e.g., `1234.1`, `1234.2`) to provide additional granularity. **BCEA is not equivalent to ISIC**; it is an extension tailored to Belize’s economic context.
- **Code Format**: All BCEA codes in this pipeline must be represented as 5-digit codes in the format `####.#` (e.g., `0112.3`, `4520.1`). Any input or output deviating from this format should raise an error or warning in the logs.
- **Scope**: The pipeline will exclusively work with BCEA’s 5-digit codes and will not fallback to or infer 4-digit ISIC codes unless explicitly required for mapping/validation purposes (e.g., cross-referencing with ISIC documentation).

### Implementation Notes
- Input validation will enforce the `####.#` format using regex (e.g., `^\d{4}\.\d$`).
- Any preprocessing step must preserve or convert data into this format.

### 2.2 Label Mapping Strategy
#### Overview
The label mapping strategy is critical to ensure consistency and coherence across the pipeline. Past LLMs have struggled with inconsistent mappings, so we will create a **single, definitive id-to-label mapping** based on all unique BCEA codes in the training data. This mapping will be reused throughout preprocessing, training, and inference.

#### Steps
1. **Extract Unique BCEA Codes**:
   - Scan the historic BCEA dataset to identify all unique 5-digit codes (e.g., `0112.3`, `4520.1`).
   - Store these in a set to eliminate duplicates.
   - Log the total number of unique codes found (e.g., “Found 1,245 unique BCEA codes”).

2. **Assign Sequential IDs**:
   - Assign each unique BCEA code a sequential integer ID (e.g., `0112.3` → `0`, `0112.4` → `1`, `4520.1` → `2`).
   - Use a dictionary or lookup table for bidirectional mapping:
     - `id_to_label`: `{0: "0112.3", 1: "0112.4", 2: "4520.1", ...}`
     - `label_to_id`: `{"0112.3": 0, "0112.4": 1, "4520.1": 2, ...}`

3. **Persist Mappings**:
   - Save the mappings to a file (e.g., `bcea_mappings.json`) in the following format:
     ```json
     {
       "id_to_label": {"0": "0112.3", "1": "0112.4", "2": "4520.1"},
       "label_to_id": {"0112.3": "0", "0112.4": "1", "4520.1": "2"}
     }
     ```
   - This file will be loaded at the start of every pipeline run to ensure consistency.

4. **Validation**:
   - Cross-check the mappings against the training data to ensure no codes are missed.
   - Log any discrepancies (e.g., “Code 1234.5 in data but not in mapping”).

5. **Handling Edge Cases**:
   - **New Codes in Test/Inference**: If a new BCEA code appears outside the training data, log a warning and assign a temporary ID (e.g., `-1`) with a placeholder label (e.g., “Unknown”). Flag for manual review.
   - **Ambiguity**: If a description maps to multiple BCEA codes in the training data, log the conflict and select the most frequent code (or use a tiebreaker rule, e.g., lowest numeric code).

6. **Documentation**:
   - Include a human-readable version of the mapping (e.g., CSV with `id`, `bcea_code`, `description`) for reference.
   - Log the creation process with timestamps and statistics (e.g., “Mapping created with 1,245 codes on 2025-03-06 14:32:10”).

#### Why This Works
- **Consistency**: A single mapping avoids redefinition across pipeline stages.
- **Scalability**: Sequential IDs simplify model training (e.g., as class indices in a softmax layer).
- **Traceability**: Persistent storage and logging ensure transparency and reproducibility.

### 2.3 Preprocessing

### 2.4 Model Training

- **Input**: Tokenized descriptions.
- **Output**: Predicted BCEA code IDs (mapped back to `####.#` format post-inference).
- **Loss**: Cross-entropy loss over the number of unique BCEA codes.
- **Logging**: Track metrics (e.g., accuracy, F1-score) per epoch with visually appealing progress bars.

### 2.5 Inference

- **Output**: Predicted BCEA codes in `####.#` format, using the `id_to_label` mapping.
- **Validation**: Ensure predictions conform to the 5-digit format; log anomalies.
